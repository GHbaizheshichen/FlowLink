# Figma 设计稿的 ArkUI 实现

基于 [HarmonyProxy Figma Make 设计](https://www.figma.com/make/dzrDluHumD6RboyI5I7vBs/)，实现首页、节点、订阅三个 NavDestination。日期：2026-10-20。

## 页面与资源

- 首页：状态标签、连接圆环、连接／断开按钮、当前节点、通过真实连接验证后才显示的出口 IP、节点与订阅入口。
- 节点：地区标记、名称、协议和选中状态。地区只匹配节点名称中明确的地区提示，无法识别时显示通用图标和服务器地址，不推测实际出口位置。
- 订阅：密码式地址输入（可主动显示）、保存刷新、加载及错误／成功反馈、清空草稿、清除保存内容的确认弹窗。VPN 活跃期间禁止编辑或更换节点。
- 所有自定义组件使用 V2 装饰器，保留真实订阅和 VPN 控制链路。
- base/en/zh_CN 提供文案；base/dark 提供相同名称的语义色值。默认跟随系统语言和外观，右上角可临时切换浅色／深色／跟随系统。手动主题选择仅在本次运行期间有效。

## 多窗口和设备适配

布局单位使用 vp，文字使用随系统缩放的 fp，不把 390×844 设计稿按比例缩放成固定屏幕。

| 场景 | 处理方式 |
| --- | --- |
| 首页容器小于 760vp | 连接区和节点信息上下排列，可垂直滚动 |
| 首页容器达到 760vp | 两个区域左右分栏；容器最大 1120vp，宽窗口居中 |
| 入口区域小于 320vp | 两张入口卡片上下排列；其余宽度并排 |
| 节点页 | 列宽 300–520vp，自适应单列或多列；列表独立滚动 |
| 订阅页 | 表单最大宽度 640vp，宽窗口居中；键盘弹出后可滚动 |
| 长节点名和英文 | 节点名最多两行、省略溢出，协议和选中标记独立占位；按钮文案可换行 |
| 大字体／低高度窗口 | 卡片和按钮使用最小高度，由内容撑开；首页和表单可滚动；主要触控目标至少 48vp |
| 系统安全区 | 沿用系统窗口和 Navigation 的安全区布局，不绘制虚假状态栏或手势条 |

首页栅格依据 `BreakpointsReference.ComponentSize` 重排，节点列表依据可用宽度计算列数；分屏及折叠后的窗口变化无需手工维护设备型号或像素尺寸监听。模块声明 phone/tablet/2in1；原生库仍使用现有 arm64 产物。

## 验证与限制

- `devecocli build`：通过，现存 VPN 代码有 3 处可能抛出异常的编译警告。
- `node scripts/check-ui-resources.mjs`：检查三种文案完整性、格式占位符、深浅色键值、主要文字对比度至少 4.5:1、资源引用与 V2 装饰器。
- HUAWEI Mate 60 Pro：安装并检查三页导航、双主题、空节点、隐藏订阅地址、清空草稿、无效地址反馈和清除确认的取消操作。没有清除保存的订阅地址。
- 本次启动自动刷新已有订阅时发生下载失败，因此手机显示真实错误和空列表；没有用虚构节点替换业务数据，也没有据此宣称连接成功。
- `devecocli check lint` 返回 Files checked: 0，不能将其视为有效 lint 验证；ArkTS 编译和资源检查是本次有效的自动检查。
- 平板、折叠屏模拟器受本机未接受的首次许可协议阻挡，尚未完成这些设备和英文／大字体环境的运行截图核验。后续由用户运行 `devecocli emulator license` 阅读并确认协议后，可启动本机 MatePad Pro 13、Mate X7 进行补测。需要确认协议是工具实际报错，不是应用要求。

建议补测窗口：320vp 窄屏、390vp 手机、600vp 分屏、840vp 展开屏、1280vp 平板；每种宽度检查中英文、深浅色、系统大字体和键盘弹出。
